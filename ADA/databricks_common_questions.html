No Simba Spark ODBC Driver

When you download Simba Spark it doesn’t necessarily download the data driver, to do this raise an I.T. ticket explaining that you have installed “Simba Spark” but the driver is missing, they will download it from the internet.

Spark

Virtual environments

Sometimes R will tell you to install pysparklyr and rerun, then when doing that it sets up a Python venv r-sparklyr-databricks-15.4 on your Onedrive, then it tries to install databricks-connect in the venv but exits with an error distutils.errors.DistutilsPlatformError: Microsoft Visual C++ 14.0 or greater is required. Get it with “Microsoft C++ Build Tools”: https://visualstudio.microsoft.com/visual-cpp-build-tools/

First step: how to get pysparklyr to not install its new virtual environment on Onedrive. You can specify the default folder for new virtual environments in the .Renvironfile by using the variable WORKON_HOME (e.g. WORKON_HOME = “C:/users/myusername” ) So first edit the file to do that, using usethis::edit_r_environ() (unless you want to use OneDrive, but it looks likely to induce lots of unnecessary syncing), and restart R.

Next step: follow the instructions at Set up Databricks personal compute cluster with RStudio – Analysts’ Guide and get to the point of connecting with:

#| sc <- spark_connect(
#|  cluster_id = Sys.getenv("DATABRICKS_CLUSTER_PATH"),
#|  method = "databricks_connect",
#|)

Install pysparklyr if it tells you to do that and try again. Eventually you will probably get a message saying it needs to install a new virtual environment with databricks-connect, and it will now make this in the new folder you specified in WORKON_HOME. If that goes without a hitch, then great, you’re done.

But if the installation fails with an error about C++ libraries, you can just install in binary mode yourself. Go (in Windows explorer) to the Scripts subfolder in the new virtual environment folder it made (probably something like C:\Users\myusername\r-sparklyr-databricks-15.4\Scripts). Right-click in the files pane and do “Open in terminal” which will open up Powershell, and in Powershell do .\python -m pip install databricks-connect. That should work to install, after which the spark-connect command should now work in R.

Temporary tables

Temporary tables do not work for Databricks runtimes before 18.1, Databricks temporary table guidance

Tables vs Volumes

It is common to confuse volumes and tables, you can find guidance on the differences in the Databricks’ guidance: volumes, importantly Volumes are more “blobby” storage so SQL works for reading tables but not for accessing volumes, which you have to do through a slightly different path Databricks’ guidance: volume paths

Retriable errors

Error: nanodbc/nanodbc.cpp:3648: HY000

[Databricks][Hardy] (35) Error from server: error code: ‘0’ error message: ‘[Databricks][Hardy] (134) File d6217fa8-e93e-49f6-9a7c-25a12d523025: A retriable error occurred while attempting to download a result file from the cloud store but the retry limit had been exceeded. Error Detail: File d6217fa8-e93e-49f6-9a7c-25a12d523025: An error had occurred while attempting to download the result file.The error is: Could not connect to server. Since the connection has been configured to consider all result file download as retriable errors, we will attempt to retry the download.’.

The way to fix this error is to set MaxErrorRetry = 0, often setting native query and enabling query result downloads helps.

#|con <- DBI::dbConnect( 
#|
#| odbc::databricks(), 
#| 
#| httpPath = Sys.getenv("DATABRICKS_CLUSTER_PATH"), 
#|
#| useNativeQuery = FALSE, 
#|
#| EnableQueryResultDownload=TRUE, 
#|
#| MaxErrorRetry=0 
#|
#|)

Splink

Some data manipulation with PySpark dataframes don’t work, for example you may encounter difficulty using Splink, here is an example of how to get around that using PySpark: Splint in PySpark.

Using packages requiring system packages

If you want to use a package that requires system packages, we recommend doing using a notebook and following the Databricks’ guidance on using libraries in r.

In general you might want to either convert the PySpark dataframe to a more manageable object: Pandas In spark and R you can use the collect() function.

I hate Mondays

You can’t change the starting day of the week away from Sunday.

Package issues

Sometimes Spark updates its packages causing our pipelines to break, there’s not much to be done in this case but to roll back the version.

Timezones

You can change timezones following this guidance: Databricks timezones.

Pushing up csv’s

Special characters in CSV files can cause an issue, if so saving the csv file in UTF-8 encoding (Databricks uses this) should solve the issue.

Memory issues

Large dataframes can cause issues with Spark, to get around this you can:

  1. use rm() and gc() to clear up as much memory as you can, removing objects you no longer need
  2. use a double-size cluster (you can set which cluster type if you’re using a personal cluster)
  3. use smaller objects (e.g. not copying all columns of a data table if you don’t need them all, or selecting a subset before you collect)
